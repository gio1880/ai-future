Build your own robot_base.py 🐍

Every great FLL team has ONE file that sets up the robot the same way every time — the "single source of truth." In this tutorial you'll type it out yourself, one section at a time, and learn exactly what every line does. By the end you'll have a real, reusable robot_base.py and understand the code well enough to fix and tune it.

Before you start: open code.pybricks.com (or the SPIKE app with Pybricks). Create a NEW file and name it robot_base.py. You'll add to this same file in every step. Copy each block in order — by the end, all the blocks together ARE the finished file.

1
The file header (docstring)
A note-to-humans at the top that says what this file is and how to use it.

A docstring is text between triple quotes """. Python ignores it when running — it's a message for the people reading your code (including future-you). Great teams always explain what a file is for.

robot_base.py
"""
robot_base.py — Single source of truth for robot setup and motion.
Based on official Pybricks v2.20.0 robotics documentation.

HOW TO USE IN A RUN FILE:
    from robot_base import robot, hub, RAM, LAM, straight, turn, arc, reset
    reset()
    straight(500)
    turn(90)
"""

"Single source of truth" means: the robot is set up in ONE place. Every run file borrows from here, so you never accidentally use two different wheel sizes in two different programs.

2
Imports — borrowing Pybricks tools
Bring in the classes and helpers we need. Nothing works without these.

Pybricks comes with pre-made tools. import is how you borrow them. You only get what you name — so import everything you plan to use.

robot_base.py
from pybricks.hubs import PrimeHub
from pybricks.pupdevices import Motor
from pybricks.robotics import DriveBase
from pybricks.parameters import Port, Direction, Stop
from pybricks.tools import wait
Line by line
from pybricks.hubs import PrimeHub
PrimeHub = the brain (your SPIKE hub). Gives you the gyro, buttons, screen, and speaker.
from pybricks.pupdevices import Motor
Motor = one motor. You'll make several (two for driving, two for attachments).
from pybricks.robotics import DriveBase
DriveBase = combines your two drive motors into one "robot" that can drive straight and turn in real millimetres and degrees.
from pybricks.parameters import Port, Direction, Stop
Port = which socket (A–F) a motor is plugged into. Direction = which way a motor counts as "forward". Stop = what to do when a move ends (HOLD / COAST / BRAKE).
from pybricks.tools import wait
wait = pause the program for a number of milliseconds. Handy between moves.
3
Robot constants — wheel & axle
Two measurements that make distances and turns accurate.

The DriveBase turns your commands (like "drive 500 mm") into wheel spins. To do that math it needs two numbers about YOUR robot. We store them in ALL-CAPS names — a Python habit that means "this is a constant, don't change it while the program runs."

robot_base.py
# ─────────────────────────────────────────────
# ROBOT PHYSICAL CONSTANTS
#
# HOW TO CALIBRATE (from official docs):
#   wheel_diameter: Run straight(1000) and measure actual distance.
#     - Traveled too short → decrease WHEEL_DIAMETER_MM
#     - Traveled too far   → increase WHEEL_DIAMETER_MM
#
#   axle_track: FIRST fix wheel_diameter above. Then run turn(360).
#     - Turned too little  → increase AXLE_TRACK_MM
#     - Turned too far     → decrease AXLE_TRACK_MM
# ─────────────────────────────────────────────
WHEEL_DIAMETER_MM = 56      # mm — measure or check the tyre sidewall
AXLE_TRACK_MM     = 122     # mm — distance between the two wheels' ground contact points
Line by line
WHEEL_DIAMETER_MM = 56
How wide your wheel is, across the middle, in mm. A bigger number means the robot thinks each spin covers more ground. The standard small SPIKE wheel is 56 mm.
AXLE_TRACK_MM = 122
The distance between where your two wheels touch the floor. This controls turning: the robot pivots around the point between the wheels, so it must know how far apart they are.
💡 Don't guess these forever. Step 13 shows you how to calibrate — run a test, measure the result, and adjust these two numbers until the robot is dead accurate.
4
Hardware — hub, motors, DriveBase
Tell the code what's plugged in where, then build the "robot."

Now we create real objects for each piece of hardware. This is where your ports matter — the letters here must match the cables on your actual robot.

robot_base.py
# ─────────────────────────────────────────────
# HARDWARE INIT
# ─────────────────────────────────────────────
hub = PrimeHub()

left_motor  = Motor(Port.A, Direction.COUNTERCLOCKWISE)
right_motor = Motor(Port.E, Direction.CLOCKWISE)
RAM = Motor(Port.F)   # Right Attachment Motor
LAM = Motor(Port.B)   # Left Attachment Motor

robot = DriveBase(left_motor, right_motor, WHEEL_DIAMETER_MM, AXLE_TRACK_MM)
Line by line
hub = PrimeHub()
Wakes up the hub so we can use its gyro, screen, and speaker. Stored in the variable hub.
left_motor = Motor(Port.A, Direction.COUNTERCLOCKWISE)
The left drive motor is in Port A. Because the two motors face opposite directions on the robot, one must be flipped so both push the robot forward — that's what Direction does.
right_motor = Motor(Port.E, Direction.CLOCKWISE)
The right drive motor is in Port E, spinning the normal way. If your robot backs up when you say forward, swap these two Directions.
RAM = Motor(Port.F)
An attachment motor (for arms, lifts, grabbers) in Port F. No Direction needed unless you want to flip it. "RAM" = Right Attachment Motor.
LAM = Motor(Port.B)
A second attachment motor in Port B. "LAM" = Left Attachment Motor.
robot = DriveBase(left, right, WHEEL, AXLE)
The star of the show. It ties the two drive motors together with your wheel & axle numbers, giving you one robot that drives in mm and turns in degrees.
💡 Match the ports! If your left motor is really in Port B, change Port.A to Port.B here. The simulator's Robot Setup panel and this file must both describe the same real robot.
5
Motion settings — speed & acceleration
Decide how fast the robot drives and turns, and how gently it speeds up.

robot.settings(...) sets the default speeds for every move. Slower is more accurate; faster is quicker but can slip. Acceleration is how gently it ramps up to speed — high acceleration can make wheels spin out.

robot_base.py
# ─────────────────────────────────────────────
# MOTION SETTINGS
# straight_acceleration can be one value OR a tuple (accel, decel)
# e.g. straight_acceleration=(400, 600) to ramp up slowly but brake fast
# ─────────────────────────────────────────────
robot.settings(
    straight_speed=600,         # mm/s — how fast it drives
    straight_acceleration=400,  # mm/s² — how quickly it reaches that speed
    turn_rate=400,              # deg/s — how fast it turns
    turn_acceleration=300,       # deg/s² — how quickly it reaches turn speed
)
Line by line
straight_speed=600
600 millimetres per second when driving straight. Lower it (e.g. 300) for precise missions; raise it for long open runs.
straight_acceleration=400
How fast it builds up to 600 mm/s. Too high and the wheels can slip at the start. A tuple like (400, 600) lets it accelerate slowly but brake quickly.
turn_rate=400
400 degrees per second when turning in place. Lower it for very accurate turns.
turn_acceleration=300
How smoothly it reaches turn speed. Smoother turns are more repeatable.
6
Turn on the gyro
Use the hub's gyro sensor for straighter driving and sharper turns.

Without the gyro, the robot guesses its heading from how much each wheel spun — which drifts over time. The gyro sensor actually measures rotation, so turns and straight lines stay true. One line turns it on:

robot_base.py
# ─────────────────────────────────────────────
# GYRO
# Docs: "Choose True to use the gyro sensor for turning and
# driving straight." Without this, heading uses encoders only.
#
# If the hub is NOT mounted flat, set top_side and front_side in
# PrimeHub() so the correct rotation axis is used.
# ─────────────────────────────────────────────
robot.use_gyro(True)
💡 Keep the robot still for a second after your program starts. The gyro calibrates at the start — if you grab the robot while it's calibrating, your turns will be off.
7
PID tuning (advanced — leave it commented for now)
The dials that control how precisely the robot drives. Start with them OFF.

PID is how the robot corrects itself while moving. It stands for Proportional, Integral, Derivative — three "dials" that decide how hard the robot fights to stay on target. Pybricks has good defaults, so we write this block but leave it commented out (the # means Python skips it). You'll only uncomment and tune it if the robot misbehaves.

robot_base.py
# ─────────────────────────────────────────────
# PID TUNING (optional — uncomment to override the defaults)
#
# DISTANCE CONTROL — accuracy of straight moves
#   kp: increase if the robot consistently stops short
#   ki: increase if it never quite reaches the target
#   kd: increase if it oscillates/overshoots at the end
#
# HEADING CONTROL — how straight the robot drives
#   kp: increase if it drifts (too high = weaving)
#   ki: removes a constant left/right bias (keep small)
#   kd: prevents overcorrection (increase if it swings side to side)
# ─────────────────────────────────────────────
# robot.distance_control.pid(
#     kp=2000,
#     ki=100,
#     kd=200,
# )

# robot.heading_control.pid(
#     kp=1400,
#     ki=60,
#     kd=500,
# )
What each dial does (in plain words)
kp — Proportional
"How hard do I push based on how far off I am right now?" The main steering strength. Too low = sloppy; too high = jittery/weaving.
ki — Integral
"How hard do I push because I've been a little off for a while?" Fixes a small constant drift or coming-up-short. Keep it small.
kd — Derivative
"How hard do I ease off because I'm approaching the target fast?" The brakes that stop overshoot and side-to-side swinging.
8
reset() — start every run clean
Your first helper function. Zeroes distance, angle, and gyro heading.

A function is a named block of code you can run whenever you want. def means "define a function." We wrap robot.reset() in our own reset() so run files can just call reset() at the top of every mission.

robot_base.py
# ─────────────────────────────────────────────
# HELPER FUNCTIONS
# ─────────────────────────────────────────────

def reset():
    """
    Call at the very start of every run.

    Docs: robot.reset() resets estimated distance and angle,
    calls stop(), and — when use_gyro(True) is set — also resets
    the gyro heading to 0. One call does all three.
    """
    robot.reset()   # stop + reset distance/angle + reset gyro heading to 0
💡 Always call reset() first. It's like setting a stopwatch to zero before a race — so every run starts measuring from the same place.
9
straight() and turn()
The two moves you'll use most — wrapped so you can add options later.

These wrap the built-in robot.straight() and robot.turn(). Wrapping them in our own functions means if we ever want to change how ALL straights behave, we change it in one place. Notice the then= option — it decides what the robot does after the move.

robot_base.py
def straight(distance_mm, then=Stop.HOLD):
    """
    Drive straight. Positive = forward, negative = backward.
    then=Stop.HOLD holds position after stopping (default).
    then=Stop.COAST lets the motors spin free — use on the last move.
    """
    robot.straight(distance_mm, then=then)


def turn(angle_deg, then=Stop.HOLD):
    """
    Turn in place. Positive = right (clockwise), negative = left.
    then=Stop.COAST on your last turn so wheels don't fight you.
    """
    robot.turn(angle_deg, then=then)
Key ideas
distance_mm / angle_deg
The parameter — the number you pass in when you call it, e.g. straight(500) or turn(90).
then=Stop.HOLD
A default value. If you don't say otherwise, the robot holds its position after the move (motors resist being pushed).
Stop.COAST
Use on the last move so the wheels go loose — handy right before you pick the robot up, so it doesn't fight you.
negative numbers
straight(-300) reverses. turn(-90) turns left. Positive turns go right (clockwise).
10
turn_to() — turn to an exact heading
A smarter turn: face a specific compass direction using the gyro.

Normal turn(90) turns 90° from wherever you're facing now. But sometimes you want to face an exact heading no matter where you started — like "point at 179°." This function reads the gyro, figures out how far to turn, and forces the turn in the direction you choose.

robot_base.py
def turn_to(target_heading, direction=-1, then=Stop.HOLD):
    """
    Turn to a specific absolute heading using the gyro.
        target_heading : the heading you want to reach (degrees)
        direction      : -1 = turn LEFT (default), +1 = turn RIGHT
    Examples:
        turn_to(179)      # turn LEFT to reach heading 179
        turn_to(90, 1)    # turn RIGHT to reach heading 90
        turn_to(0)        # turn LEFT back to the start
    """
    current = hub.imu.heading()
    delta = target_heading - current

    if direction == -1:
        # Force LEFT (counterclockwise = negative)
        if delta > 0:
            delta -= 360
    else:
        # Force RIGHT (clockwise = positive)
        if delta < 0:
            delta += 360

    robot.turn(delta, then=then)
How the tricky part works
current = hub.imu.heading()
Ask the gyro: "which way am I facing right now?" (in degrees).
delta = target_heading - current
How far I need to turn = where I want to be − where I am.
if direction == -1 and delta > 0: delta -= 360
You asked to go LEFT, but the shortest turn was to the right. Subtracting 360° flips it into the equivalent left turn instead.
else: if delta < 0: delta += 360
Same idea for a forced RIGHT turn: if the number came out negative (left), add 360° to make it a right turn.
robot.turn(delta)
Finally, do the turn we calculated.
💡 Why force a direction? Sometimes turning the "long way" avoids hitting a wall or a mission model. direction lets you choose.
11
arc() — drive curves
Drive a smooth curved path instead of straight-then-turn.

An arc is part of a circle. Curving can be faster and smoother than "straight, stop, turn, straight." You give it a radius (how tight the curve is) and either an angle or a distance.

robot_base.py
def arc(radius_mm, angle_deg=None, distance_mm=None, then=Stop.HOLD):
    """
    Drive a curved arc.
      radius > 0 → curves RIGHT.  radius < 0 → curves LEFT.
      Give EITHER angle_deg OR distance_mm (not both).
    Examples:
      arc(200, angle_deg=90)     # curve right, quarter circle, radius 200
      arc(-150, angle_deg=-45)   # curve left, in reverse
      arc(300, distance_mm=400)  # curve right, 400mm along the arc
    """
    robot.arc(radius_mm, angle=angle_deg, distance=distance_mm, then=then)
Key ideas
radius_mm
How wide the curve is. Small radius = tight curve; big radius = gentle curve. Positive curves right, negative curves left.
angle_deg=None / distance_mm=None
None means "not set." You fill in ONE of them: how far around the circle (degrees) OR how far to travel (mm).
12
Use it in a run file
Your setup file is done! Now write a mission that borrows from it.

🎉 robot_base.py is finished — that's your single source of truth. For each mission, make a new file (e.g. run1.py) that imports from it. Notice how short and readable a run becomes:

run1.py
from robot_base import robot, hub, RAM, LAM, straight, turn, arc, reset

reset()              # always start clean
straight(500)        # forward 500 mm
turn(90)             # turn right 90°
straight(300)        # forward 300 mm
RAM.run_time(500, 1000)   # spin the right attachment motor

Because all the setup lives in robot_base.py, every run file stays tiny and easy to read — and if you re-tune the robot, every run improves at once.

13
Calibrate your robot
Make distances and turns dead accurate — the final, most important step.

Your robot won't be perfectly accurate until you calibrate the two numbers from Step 3. Do these in order — wheel diameter first, then axle track — because turning depends on driving being correct.

  • Step A — Wheel diameter. Run straight(1000) and measure how far it actually went. Traveled too short → decrease WHEEL_DIAMETER_MM. Too far → increase it. (Math shortcut: new = old × (1000 / actual).)
  • Step B — Axle track. Once distance is right, run turn(360). The robot should end facing the same way. Turned too little → increase AXLE_TRACK_MM. Too far → decrease it.
  • Step C — Heading drift. If it drifts while driving straight, raise heading_control kp a little. If it starts weaving, raise kd.
  • Step D — Overshoot. If it overshoots or wobbles at the end of a move, lower distance_control kp and raise kd.
  • Step E — Gyro quirk. Every gyro is slightly different. If a 90° turn lands at 87°, tell it turn(93) to compensate.
  • Step F — Last move. Use then=Stop.COAST on your final straight/turn so the robot doesn't fight you when you pick it up.
💡 Calibrate the simulator's Robot Setup panel to the same wheel/axle numbers and your simulated runs will match real life closely.
